# US-005: Understand Graphics Compatibility and Configuration

## As a

WoW Forever user on Android

## I want

to identify my GPU, its support evidence, and the configuration WoW will use

## So that

I can distinguish tested devices from unknown ones as Mali support is expanded.

This records the [approved plan](../planning/done/launcher-gpu-compatibility-plan.md)
and the user's explicit request to identify known graphics configurations and
show unknown compatibility within the APK.

## Use Cases

- **US-005-UC-01**: View GPU identity and compatibility status on the welcome screen.
- **US-005-UC-02**: View the planned/prepared graphics configuration and evidence.
- **US-005-UC-03**: Recheck or share a minimal diagnostic report.

## Acceptance Criteria

- **US-005-AC-01** (UC-01): show the detected GPU and either a device-specific
  historical match or “Compatibility unverified.” A Mali name or available
  Vulkan API alone is insufficient.
- **US-005-AC-02** (UC-02): show PanVK, Wine, DXVK, and renderer versions/profile,
  distinguishing planned/prepared from loaded and from gameplay rendering.
- **US-005-AC-03** (UC-01): errors, timeouts, or incomplete data do not produce
  positive support claims, block the UI, or create unbounded native workers.
- **US-005-AC-04** (UC-03): recheck/details/share omit accounts, serial, IMEI,
  credentials, personal paths, and stack traces.
- **US-005-AC-05** (UC-01, UC-02): this is informational; it does not start
  WoW/Wine, change drivers/permissions, or block Launch for unknown combinations.

## Edge Cases

- Same G610 on another device, OS, kernel, or profile; G615 is not G610.
- EGL read blocks; timeout and late result; Activity closes or is recreated.
- Vulkan version is declared by Android without a measured Wine backend.
- Prepared configuration differs from the known combination and invalidates the
  historical match.

## Functional Requirements

### US-005-FR-001

- **Derives from:** US-005-AC-01
- **Pattern:** Event-driven

WHEN the welcome screen opens, THE SYSTEM SHALL show a graphics reading with its
provenance and classify compatibility by hardware, operating-system, and profile
combination rather than by GPU family alone.

### US-005-FR-002

- **Derives from:** US-005-AC-02
- **Pattern:** State-driven

WHILE graphics configuration is shown, THE SYSTEM SHALL distinguish the
planned/prepared profile from its effective load and historical evidence from a
current test.

### US-005-FR-003

- **Derives from:** US-005-AC-03
- **Pattern:** Event-driven

WHEN the graphics reading fails or times out, THE SYSTEM SHALL show an unknown
state without publishing late results or creating more than one active EGL worker
in the process.

### US-005-FR-004

- **Derives from:** US-005-AC-04
- **Pattern:** Event-driven

WHEN the user requests a recheck or sharing, THE SYSTEM SHALL return the current
state or a bounded error and export only minimal technical identity without secrets.

### US-005-FR-005

- **Derives from:** US-005-AC-05
- **Pattern:** Ubiquitous

THE SYSTEM SHALL keep detection separate from startup and driver selection,
without changing the existing profile or blocking unknown GPUs.

## Non-Functional Requirements

- **US-005-NFR-001**: visual wait is bounded to 1500 ms; the query runs off the UI
  thread and EGL cleanup occurs on returning paths. A native block cannot safely
  be interrupted, so the global lease remains held until the worker returns.
- **US-005-NFR-002**: use a versioned local matrix, with no telemetry or persistent
  cache that survives OS/driver/profile changes. Results are explicitly scoped to
  the current session.
- **US-005-NFR-003**: sources and APK are audited; no new assets, runtime, or JNI
  are introduced.

## Test Cases

```gherkin
# US-005-TC-001 (validates US-005-FR-001)
Scenario: Match a known historical combination
  Given xaga G610 MC6, API 34, kernel 5.10.209, and the fixed tested profile
  When the compatibility matrix is queried
  Then historical rendering evidence is shown
  And gameplay or current component loading is not claimed

# US-005-TC-002 (validates US-005-FR-001)
Scenario Outline: Combination is not known
  Given <field> differs from the tested combination
  When the compatibility matrix is queried
  Then compatibility is shown as unverified

  Examples:
    | field       |
    | device      |
    | GPU         |
    | API         |
    | kernel      |
    | profile     |

# US-005-TC-003 (validates US-005-FR-002)
Scenario: Planned does not mean loaded
  Given WoW has not yet been launched
  When the profile is displayed
  Then it is labeled planned
  And effective loading remains unverified

# US-005-TC-004 (validates US-005-FR-003)
Scenario: Timeout and late response
  Given the EGL worker remains active after timeout
  When the screen is recreated or another check is requested
  Then no second worker is created
  And the late result is not published as success

# US-005-TC-005 (validates US-005-FR-004)
Scenario: Share a minimal diagnostic report
  Given a graphics reading or error is available
  When sharing is opened
  Then the report omits personal identifiers, credentials, and private paths

# US-005-TC-006 (validates US-005-FR-005)
Scenario: Check compatibility without starting the game
  Given the GPU has no known match
  When the welcome screen is displayed
  Then Wine is not started and drivers are not changed
  And the Launch action remains available
```

## Assumptions

- The proof of concept keeps a fixed profile rather than selecting backends
  automatically.
- GLES identity and Android's declared Vulkan API do not establish the effective
  Vulkan capabilities DXVK will see. The first release does not add a native probe
  to measure those capabilities.

## Open Questions

- Adding entries to the compatibility matrix requires evidence and review for each
  device/profile combination.
- The first known entry proves historical rendering, not authentication, world
  access, or gameplay.
