# US-001: Provision the Client from the CDN

## As a

wowforever project maintainer

## I want

to obtain, verify, and repair a WoW Classic Beta 1.60.1 client installation
directly from Blizzard's CDN, without Battle.net or Windows

## So that

I have the client expected by the Classic Forever launcher for subsequent
Android, Forever-compatibility, and gameplay work.

The verification scope in this specification reflects current `forever-client`
behavior, as directed by the user on 2026-10-21: `verify` checks loose files in
the install manifest only. It does not verify CASC objects under `Data/` and must
not be described as whole-client integrity verification.

## Use Cases

- **US-001-UC-01**: Resolve the target build published on the CDN for product
  `wow_classic_beta`.
- **US-001-UC-02**: Install the client in a destination directory.
- **US-001-UC-03**: Verify the loose install-manifest files in an installed client.
- **US-001-UC-04**: Repair missing or corrupt loose install-manifest files.

## Acceptance Criteria

- **US-001-AC-01** (UC-01): `resolve` returns the active build's BuildId,
  `VersionsName`, build-config hash, and CDN-config hash in a readable format.
- **US-001-AC-02** (UC-01): the queried product is `wow_classic_beta` (not
  `wow_forever`), and the result comes from the public CDN without authentication.
- **US-001-AC-03** (UC-02): after `install`, the destination contains `WowB.exe`,
  the `Data/` CASC storage, and build metadata.
- **US-001-AC-04** (UC-02): the installation targets a build supported by the host
  provisioning contract (`69913`, `69977`, or `70009`); by default it targets the
  active build. This list describes the host CLI, not Android ARM64 build admission.
- **US-001-AC-05** (UC-02): an interrupted installation resumes without
  re-downloading content already present and verified by the installer.
- **US-001-AC-06** (UC-03): `verify` checks the expected loose install-manifest
  files against CDN-manifest metadata, reporting missing and corrupt files
  separately. CASC objects under `Data/` are outside its verification scope.
- **US-001-AC-07** (UC-03): `verify` exits with status 0 when all expected loose
  files are valid and a non-zero status when discrepancies are found.
- **US-001-AC-08** (UC-04): `repair` re-downloads only missing or corrupt
  loose-manifest files and leaves those files valid for `verify`.
- **US-001-AC-09** (UC-02/03/04): no operation modifies `Config.wtf` or the
  client's key store; provisioning operates on files only.

## Edge Cases

- The active CDN build changes between `resolve` and `install`.
- The destination already contains another build (different hashes).
- Network connectivity is lost partway through a file download.
- A file is present but has an incorrect hash (silent corruption).
- Disk space is insufficient: the all-tags product estimate is about 128 GB,
  substantially more than the `Windows` + `x86_64` + `enUS` subset.
- A CASC object is missing or corrupt even though loose-file `verify` succeeds;
  this command does not detect that condition.

## Functional Requirements

### US-001-FR-001

- **Derives from:** US-001-AC-01, US-001-AC-02
- **Pattern:** Event-driven

WHEN the user runs `resolve`, THE SYSTEM SHALL query the versions endpoint for
`wow_classic_beta` and display the BuildId, VersionsName, build-config hash,
CDN-config hash, and build name.

### US-001-FR-002

- **Derives from:** US-001-AC-03
- **Pattern:** Event-driven

WHEN the user runs `install <dir>`, THE SYSTEM SHALL download the target build
from the CDN and materialize `WowB.exe`, `Data/` storage, and build metadata in
`<dir>` for the supported host-client profile.

### US-001-FR-003

- **Derives from:** US-001-AC-04
- **Pattern:** Conditional

IF the target build is not in the host CLI's supported list (`69913`, `69977`,
`70009`), THE SYSTEM SHALL explicitly warn the user before continuing.

### US-001-FR-004

- **Derives from:** US-001-AC-05
- **Pattern:** State-driven

WHILE installation state for the same build exists in `<dir>`, THE SYSTEM SHALL
resume installation while omitting content already verified by the installer.

### US-001-FR-005

- **Derives from:** US-001-AC-06, US-001-AC-07
- **Pattern:** Event-driven

WHEN the user runs `verify <dir>`, THE SYSTEM SHALL check expected loose
install-manifest files against CDN-manifest metadata, classify each discrepancy
as missing or corrupt, and return exit status 0 when all expected loose files
are valid or a non-zero status otherwise. THE SYSTEM SHALL NOT report CASC
objects under `Data/` as verified by this command.

### US-001-FR-006

- **Derives from:** US-001-AC-08
- **Pattern:** Event-driven

WHEN the user runs `repair <dir>`, THE SYSTEM SHALL download only missing or
corrupt loose install-manifest files and leave those files in a state accepted
by `verify`.

### US-001-FR-007

- **Derives from:** US-001-AC-09
- **Pattern:** Ubiquitous

THE SYSTEM SHALL limit provisioning operations to files and SHALL NOT modify
`Config.wtf`, `WTF/BetaSuspendedTest.wtf`, or the client's key store.

### US-001-FR-008

- **Derives from:** US-001-AC-03
- **Pattern:** Conditional

IF the user requests a minimal installation containing only loose install-manifest
files, THE SYSTEM SHALL install `WowB.exe` and its dependencies without populating
all CASC architectures, leaving the client to obtain additional content from the CDN.

## Non-Functional Requirements

- **US-001-NFR-001**: `resolve` responds in under 30 seconds on a typical home
  network.
- **US-001-NFR-002**: download parallelism is bounded (at most 12 global
  connections and at most 3 per host) and does not evade CDN limits.
- **US-001-NFR-003**: `install` is idempotent; rerunning it on a complete
  installation does not re-download valid content.
- **US-001-NFR-004**: required disk space for the `Windows` + `x86_64` + `enUS`
  subset is reported before downloading begins.

## Assumptions

- `[ASSUMPTION]` The NGDP product identifier is `wow_classic_beta`; its versions
  endpoint is available without authentication.
- `[ASSUMPTION]` The launcher locates the game by the presence of `WowB.exe` in
  the game directory; materializing that executable alongside `Data/` is sufficient.
- `[ASSUMPTION]` `enUS` is the text locale used by the launcher (`textLocale=enUS`).

## Open Questions

- Does the launcher require the game directory to be named exactly
  `_classic_beta_`, or does it accept any directory containing `WowB.exe`? Verify
  against the launcher implementation.
- Is the `Windows` + `x86_64` + `enUS` subset sufficient to start the client, or
  does it also require `Alternate`/`HighRes`?
- `[PENDING]` What mechanism, if any, will verify CASC objects under `Data/`?
  Current `forever-client verify` does not provide that coverage.
